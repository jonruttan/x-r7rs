# known-failures.txt -- the specs this bundle is known to fail.
#
# One "UNIT: TEST" per line, matching the runner's own `FAIL:` lines verbatim.
# Blank lines and #-comments are ignored.
#
# BY NAME, NOT BY COUNT.  A budget of "43 failures" is satisfied by fixing one
# and breaking another, which is the exact event a ratchet exists to catch.
#
# THE LIST MAY ONLY SHRINK.  tests/spec-gate.sh is red when a failure appears
# that is not here, AND when a line here starts passing.
#
# MEASURED ON A QUIET MACHINE, and that is not fussiness.  This suite reported
# 49, 58 and 247 failures on three consecutive runs of the same tree, with
# `Segmentation fault: 11` and 207 batches dying mid-run -- all of it caused by
# an orphaned x-bin left holding a core, not by anything in the bundle.  With
# the machine clear the set is 43, identical across runs.  A number taken while
# something else is running is a number about the machine, so take it twice and
# make sure nothing else is running.
#
# AGAINST x-lang v0.8.1, which pins x-engine-c v0.1.4 -- what lang.xon declares
# and what CI checks out.  The set is 43 on v0.1.2, v0.1.3 and v0.1.4 alike, so
# nothing here is waiting on the engine pin; measured on all three.
#
# v0.1.4's reader fix took x-r5rs from nine failures to none, and moved nothing
# here: this bundle's debt is bytevectors, error objects and guard, none of
# which the reader touches.
